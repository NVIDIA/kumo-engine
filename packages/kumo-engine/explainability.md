# Training explanations

The local Python API retrieves diagnostics already generated by `Trainer.fit()`.
It does not retrain a model or generate explanations for new entities or batch
predictions. Explanation generation can fail without invalidating training.

## Access the selected training run

Capture the result returned by your existing training call:

```python
training_result = trainer.fit(training_table, snapshot=snapshot)
explanations = training_result.explanations
print(explanations.run_root)  # retain this directory to reopen diagnostics
print(explanations.trial_root)  # selected TEST explanation trial
print(explanations.availability)
```

Attachment is lazy: fitting retains paths and generation status, without reading
the artifact bodies or retaining the core trainer. Availability checks file
presence; they do not validate the contents or load graph bodies. The keys are
`gradient`, `cohorts`, and `samples`. Each entry has `available`, `path`, `reason`,
and `generation_failure`. Missing artifacts are never zero-valued explanations.
A failed generation can still leave readable partial artifacts.

When unavailable, `reason` distinguishes known disabled or failed generation,
model-only loading, and an unknown cause. Historical files do not establish why
an artifact is absent. Generation status captured during fit is not archived
by this API; reopening reports unknown causes for missing artifacts.

To reopen a retained run without training:

```python
from kumo.engine import TrainingExplanations

explanations = TrainingExplanations.load("/path/to/retained/run")
```

Supply the run containing `models/<task>/automl/best_trainer.json`. The loader
requires one selected-trial record and rejects ambiguity. It uses the selected
original trial and its recorded `config.json` train/validation refit state.
Missing or invalid refit state raises `InvalidRunError`; directory presence
alone does not select a refit. TEST explanations use `_refit_trainval` when
recorded and do not select `_refit_full`. Copied runs resolve selection within
the supplied run, rather than following an old absolute path.

Published model bundles omit these diagnostics. `Trainer.load(bundle)` leaves
its result's explanations unavailable with reason `model_only`; retain and
open the training run separately. Clearing the scratch run removes access.

## Notebook diagnostics

```python
from IPython.display import display

display(explanations.visualize(max_samples=12))
```

The view combines split-qualified metrics, learning history, recorded trials, input sensitivity, cohorts, and retained examples.
Known disabled or failed generation is shown separately from artifact retention and producer eligibility; retained artifacts remain inspectable.
Generation status remains unknown on reopening because this API does not archive it.
Select a column's cohort action to inspect its recorded predictions and targets, or select an available example to inspect its sampled nodes, relations, and feature scores.
Selected regression, binary, multiclass, and multilabel examples also show predictions and observed targets from the matching collector output, when retained and valid.
Selected static and temporal link-prediction examples show ordered predicted and observed TEST original item IDs, with at most 100 rows displayed per list.
Empty lists contain zero recorded IDs; null lists are not recorded.
The explanation retrieval list can differ from query TOP K; observed links are recorded TEST targets rather than a history of all links, and no retrieval scores, probabilities, or per-item sensitivity breakdown are retained.
Regression values use recorded target units; binary predictions are positive-class probabilities with observed targets encoded as 0 or 1.
Class-keyed outputs align recorded label probabilities with observed membership indicators (0 or 1), preserving exact values without renormalization.
Multilabel probabilities are independent and observed memberships are nonexclusive, so their sums can exceed one.
The view shows up to 100 retained labels in a bounded disclosure and identifies coverage.
Complete retained outputs remain in the matching TEST fit's `subgraph_collector/test/output/<collector_id>.json`; the artifact does not record total class coverage or which label caused selection.
Missing, invalid, limited, or unsupported output remains explicit while sampled structure stays available.
Scores describe recorded behavior; the view does not prescribe model changes or start training.

## Gradient scores

```python
if explanations.availability["gradient"].available:
    scores = explanations.gradient_scores()  # kumoapi GraphGradientScore
    frame = scores.to_pandas()  # table, column, score
    figure, axis = explanations.plot_gradient(top_k=20)
    figure.savefig("training-importance.png", bbox_inches="tight")
```

Bars use table-qualified column labels. Returned figures and axes support
customization and saving; plotting never calls `show()`. The explanation
helpers import Matplotlib only when plotting is requested. `pip install
"kumo-engine[plots]"` explicitly requests the plotting dependency. This extra
is currently redundant with core's existing required Matplotlib dependency:
the wider `import kumo.engine` also imports Matplotlib through its training
workflow. Explanation retrieval adds no plotting import, but the complete SDK
cannot yet be used in a Matplotlib-free installation. Decoupling those existing
core imports and dependencies is outside this change.

The training producer normalizes column scores by their global total when it
is positive and writes `scores.csv` with six decimal places. Retrieval preserves
those recorded values, including zero scores and rounding; it cannot restore
unnormalized gradients. Rounded values need not sum exactly to one. Plots do
not apply another normalization or convert scores to percentages.

## Column cohorts

Discover the complete `(table_name, hop, col_name)` keys and class labels first:

```python
print(explanations.cohort_keys())
key = ("users", 0, "age")  # choose a key from the printed output
print(explanations.classes(key))
```

For class-keyed multiclass or multilabel outputs, explicitly choose a label
returned by `classes(key)`:

```python
cohort = explanations.cohort(key, class_name="True")  # use your class label
figure, (prediction_axis, population_axis) = explanations.plot_cohort(
    key, class_name="True")
```

For regression or binary positive-class vectors, `classes(key)` is empty:
omit `class_name`. No missing negative-class vector is fabricated.
`cohort()` returns the shared `ColumnCohorts`
schema; class selection validates the label while retaining its full class
dictionaries. `column_analysis()` returns the validated `ColumnAnalysisOutput`.
The upper plot shows predictions and observed targets when recorded. The lower
plot shows population shares on a separate axis.

Cohort `prediction_score` measures variation between cohorts. It is a different
quantity from gradient attribution. Neither establishes causation. Duplicate
keys, inconsistent classes, nonfinite scores, misaligned lengths, and invalid
population shares raise errors instead of producing misleading plots.

## Sampled graph context

```python
samples = explanations.samples()  # references, without loading graph bodies
for reference in samples:
    print(reference.artifact_id, reference.categories, reference.original_ids)
    if reference.available:
        graph = explanations.sample(reference.artifact_id)  # kumoapi Subgraph
        print(graph.subgraph_store, graph.feature_store)
```

Graphs retain recorded structure, features, optional scores, timestamps, and
aggregated nodes. A reference can exist for a missing graph; check `available`.
`artifact_id` is collector-local. Optional `original_ids` are recorded entity
identifiers organized by sampling category; they are not interchangeable with
collector IDs. Without those mappings, arbitrary original-key lookup is not
available. These bounded samples are training context, not explanations for
every entity. The notebook view presents recorded nodes, relations, and feature
values; it does not provide arbitrary-entity lookup.

## Availability and validation

| Training task | Producer capabilities, subject to model and retained outputs |
| --- | --- |
| Binary, multiclass, multilabel classification; regression | Gradient scores, column cohorts, sampled graphs |
| Static or temporal link prediction | Column cohorts require node prediction; gradient scores and sampled graphs exclude two-tower modules |
| Forecasting | Gradient scores; column cohorts and sampled graphs are not generated by these producers |

The table describes producer eligibility, not a guarantee that a particular run
contains every artifact. `training_job.disable_explain`, model support, failed
generation, sampling, and cleanup affect availability.

Public errors are exported from `kumo.engine`: `ExplanationUnavailableError`
for missing artifacts, `InvalidExplanationError` for malformed data, and
`InvalidRunError` for an invalid or ambiguous retained-run selection. Unknown
cohort keys or classes raise explicit lookup/selection errors. Availability
can change if files are removed after checking it.

The implementation's small fixtures use the shared producer schemas and CSV/JSON
writers from source revision `74465d01`, plus mocked training integration and
headless plotting. They are not retained artifacts from a released v1.0 training
run. Released v1.0 artifact compatibility remains unverified. Website guide
source and publication are maintained separately; this local guide does not
update or publish the website.
