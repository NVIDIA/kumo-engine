# Examples

Each example here solves one modeling problem from start to finish, in a
Jupyter notebook. The data is synthetic and generated by the notebook itself, so
there's nothing to download, and each one runs in under a minute on a laptop
CPU.

- [hm-recommendation](hm-recommendation/) ranks the products a retail customer
  is likely to buy next week, using a graph neural network over their recent
  purchases. It runs on the in-memory engine for now, because the
  DiskGraph engine doesn't support candidate lists yet.
- [pragma-fraud](pragma-fraud/) pre-trains a transaction model on banking data,
  then fine-tunes it to flag users who are about to see fraud. It runs on
  the DiskGraph engine.
- [churn](churn/) predicts which customers will stop buying, using classic
  point-in-time features such as counts and sums over recent weeks. It runs on
  the DiskGraph engine, and also shows how to serve a single prediction.

If you're new to kumo-pytorch, the [guide](../docs/README.md) explains the
ideas these examples use.

## Running them

The notebooks need kumo-pytorch with its `notebooks` extra, which
[installation](../docs/installation.md) covers. DiskGraph is installed with
kumo-pytorch, so the pragma-fraud and churn examples need nothing more. Then open
`walkthrough.ipynb` in the example's folder with Jupyter (`uv pip install
jupyterlab`).

You can also run every notebook headless, the way kumo-engine's CI does. Set up
the kumo-engine checkout as described in
[running the tests and notebooks from a checkout](../docs/installation.md#run-the-tests-and-notebooks-from-a-checkout),
then, with that environment active, run this from `packages/experimental/kumo-pytorch`:

```bash
python -m pytest -m notebook
```

## What's in each folder

Besides the notebook and a README, each folder has a small Python module with
the model the notebook trains. You'll also find a few JSON files that the
notebook writes, such as `contract.json`, so you can see what it produces
without running it. Larger outputs like the data, trained weights and saved
artifacts go to a temporary directory.

## Changing an example

Notebooks are committed without outputs, so clear them before you commit:

```bash
jupyter nbconvert --clear-output --inplace examples/*/walkthrough.ipynb
```

The test run above also checks that each notebook still writes the same JSON
files that are committed. If your change is meant to alter them, regenerate
them and commit them along with it. Name one or more examples, or none to
regenerate all of them:

```bash
python -m tests.test_notebooks --write churn
```
