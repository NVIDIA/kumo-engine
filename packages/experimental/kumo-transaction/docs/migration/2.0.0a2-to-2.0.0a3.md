# Migration from 2.0.0a2 to 2.0.0a3

2.0.0a2 is tag `v2.0.0a2`. 2.0.0a3 builds a token cache from any tokenizer and data
source that implement the columnar protocols, holds training batches on the GPU, and
runs the training step with fewer host syncs and less memory (measured in the
CHANGELOG's `tfm.kernels.linear_cross_entropy` entry). Every config that
2.0.0a2 ships loads unchanged, so `tfm migrate-config` is not needed. Code that calls
the APIs below changes, and every token cache is rebuilt.

## Dependencies

2.0.0a3 requires torch 2.9 or newer, the first release with `torch.optim.Muon`.
`import tfm.training` fails on an older torch.

Contributors need uv 0.13.8 (`uv self update 0.13.8`, or `pip install uv==0.13.8`):
`pyproject.toml` pins it with `[tool.uv] required-version`, so another uv refuses
`uv lock`, `uv sync` and `uv run` in the project.

## Configs

A config with `features.tokenizer: event_fields` and `features.categorical_keys` is
refused: `event_fields` ignored the key, since its 12 fields are fixed. Remove it.

## Event data

A book whose events carry a text field named like a label (`is_fraud`, `fraud`,
`chargeback`, `chargeback_resolved`, `label`, `target`), or a field whose name matches
one of these only once surrounding spaces are removed (` Fraud `), is refused with the
field's name. 2.0.0a2 checked only categorical and numeric field names, ignoring case
but not spaces.
Rename the field, or leave it out of the book.

## Code

`tfm.objectives.mlm.apply_mlm_mask` keeps its signature. The masking rates are the
same, but the per-key draws are a hash of the key id and a per-row seed, so a seeded
run masks different tokens than in 2.0.0a2.

`EventFieldsTokenizer` and `FlatKeyValueTokenizer` hold a `ValueVocabulary` and
`KeyValuePairs` instead of subclassing `KeyValueTimeTokenizer`. Code that read
`tokenizer.field_kind`, `cat_vocab`, `token_to_id` and the other vocabulary fields
reads them from `tokenizer.vocabulary`; `key_vocab` and `field_tokens` move to
`tokenizer.pairs`. `KeyValueTimeStats` is
`tfm.features.tokenizers.vocabulary.KeyValueStats`, and
`KeyValueTimeConfig.fit_value_cap` is `KeyValueTimeConfig.vocabulary().fit_value_cap`.
`EventFieldsTokenizer` and `FlatKeyValueTokenizer` no longer save or load fitted state
(`state_dict`, `from_state`); refit them, or use `key_value_time` for a
checkpointed or cached run.

## Token caches

A key-value-time token cache built by 2.0.0a2 or earlier has format 1; 2.0.0a3
reads format 4 only and refuses older ones, including formats 2 and 3 from
unreleased development builds. A format 4 cache built before `data.amount_field`
existed is refused too, because the field is part of a cache's identity. So is
a cache built with `features.exclude_keys` before the build dropped those keys,
or one built before the key-value-time tokenizer recorded `event_encoding` or
before a subset's user ids were hashed as a JSON array.
Rebuild it from the same config:

```bash
uv run tfm cache-tokens --config path/to/config.yaml
```

The rebuilt cache holds the same tokens, except for hashed keys, whose buckets
now come from MurmurHash3 instead of BLAKE2b. Code that read the cache's
`.npy` files directly reads `TokenCache`'s arrays instead: each is a
`ShardedArray`, indexed like a NumPy array, and `np.asarray` gives the whole
array. Code that built a `CacheRequest(root=path, ...)` passes
`source=PragmatiqColumns(path)` (`tfm.data.adapters.pragmatiq_columns`)
instead, and `tokenizer=KeyValueTimeTokenizer(config)` instead of
`tokenizer=config`. A cache built before the tokenizer's import path and
`settings()` joined its identity is refused once; rebuild it with the command
above. `cache.user_ids[i]` becomes `cache.user_ids([i])[0]`, and
`cache.user_index[u]` becomes `cache.user_index([u])[0]`, which is -1 for a user
the cache does not hold.

Per-event arrays now travel by name. Code that read `batch.hour`, `batch.dow`
or `batch.dom` reads `batch.event_array("hour")` (or `batch.events["hour"]`),
code that built a `KeyValueTimeBatch` or `EncodedKVTRecord` passes
`events={"hour": ..., "dow": ..., "dom": ...}`, and `cache.hour` becomes
`cache.events["hour"]`. `CachedKeyValueTimeTokenizer` is `CachedTokenizer`, and
`cache.tokenizer(profiles)` becomes `cache.tokenizer(profiles,
max_events=config.data.sequence_length)`. A custom model that reads a
per-event array sets `event_arrays = (...)` so a run checks the cache for it
before the first step.

A recipe's cache is reached through its tokenizer's format. Code that imported
`cache_request`, `flat_cache_request` or `cache_path` from `tfm.runtime.token_cache`
imports them from `tfm.data.token_cache.columnar`, `tfm.data.token_cache.flat` and
`tfm.data.token_cache.formats`; `build_recipe_cache` and `open_recipe_cache` stay.
Code that tested `isinstance(data.token_cache, ...)` calls `data.cache_format`
instead.
