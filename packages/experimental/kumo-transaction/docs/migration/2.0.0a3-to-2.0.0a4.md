# 2.0.0a3 to 2.0.0a4

2.0.0a4 adds experimental relational graph recipes. Existing 2.0.0a3 token
recipe YAML keeps its meaning. Graph models, objectives and their artifacts are
new in this release; they do not replace token-model checkpoints.

## Custom training batches

The eager trainer consumes two declared capabilities: `for_execution(device)`
and `has_supervision`. Subclass the public batch protocol to inherit ordinary
full-transfer and supervised-step defaults:

```python
from tfm.contracts.training import TrainableBatch

class MyBatch(TrainableBatch):
    def to(self, device):
        # Return your batch with its tensors on device.
        ...
```

A structural implementation can instead implement both members explicitly.
`has_supervision` is host metadata established during batch construction, not
a device scalar read. False batches have no optimizer or training-buffer
updates. `for_execution` may retain validation metadata on CPU, while `to`
continues to mean a complete device copy. Built-in token batches keep complete
transfer; validated graph batches provide execution views.

## Graph configuration and stages

`tfm.config.RecipeConfig` is the schema for every recipe. `recipe_family` is a
registered runner name or `package.module:function`, not a separate schema.
The graph family uses the same adapter/tokenizer registries as token recipes.
Graph-specific clocks and neighborhood settings are described in the
[configuration reference](../reference/config-schema.md#experimental-graph-recipe-family).

Set `runtime.stage` explicitly when separating training:

- `full` (default): train the encoder, downstream model where applicable, and
  comparison arms. Binary labels are required because these runs train/score
  binary tasks, including when the encoder objective is self-supervised.
- `pretrain`: `train` builds only the graph encoder stage. With
  `training.objective: future_subgraph`, it neither loads task labels nor
  constructs binary controls/probes. Binary encoder training still requires
  available task labels. The unused probe cutoff is not a pretraining coverage
  requirement; complete target horizons and availability bounds still are.
- `downstream`: load `runtime.encoder_checkpoint`, then train the downstream
  model and matched binary control. A hybrid freezes the imported encoder;
  a graph-only run fine-tunes it with binary supervision. Future targets are
  not rebuilt. Set the graph-only composition objective to `binary`.

Every trained graph run writes `encoder.pt`, a plain PyTorch state dictionary,
and `encoder.manifest.json`, bound by a SHA256 hash. A custom model can load
that state dictionary directly. The managed downstream path additionally
checks the feature transform, graph schema, module types and Engine version
before installing any state. Preserve the manifest for managed reuse. Full
experiment bundles keep embedded metadata authoritative for identity checking.

## Public graph-context hooks

`tfm.layers.profile_event_decoder.encode_events` returns event summaries and
token states. `decode_history(..., context=...)` combines summaries with a
profile and an optional graph field, then returns decoder states and their
mask. A deferred context is called after event encoding and before profile
encoding. `ProfileEventStack` describes these modules by call signature;
`embed_tokens` is the public token-embedding method.

`GNNSequenceModel` also accepts a custom history module/spec, `Readout`, and
binary head. The graph field remains cutoff-level information: it cannot be
used for within-history next-event objectives or surprise. See the
[extension guide](../reference/extending.md#graph-composition-extension-points).

## Execution and support limits

Graph batches validate on CPU; copied tensors and their CPU sources remain
read-only and mutation-guarded. Named event arrays, including custom configured
time features, transfer with history inputs. Future-subgraph loss uses
fixed-shape masking, and graph CUDA parity checks use deterministic algorithms.

The graph family currently supports single-process eager training. Distributed
or packed graph execution remains unsupported and fails explicitly. These
recipes are synthetic wiring examples, not a downstream quality result.

## Cache validation hardening

Subset-cache population identities hash a canonical JSON array of sorted unique
user IDs, keeping delimiters inside IDs distinct. Rebuild a subset cache if its
population identity no longer matches. Per-event cache arrays must be integers
or booleans; fractional arrays are rejected before writing or opening rather than narrowed
silently during history collation. Custom columnar sources receive the same
implicit transaction-source token as the object encoder when the field is absent.

Key-value-time cache identities now record `event_encoding: implicit-source-v1`.
Rebuild an older key-value-time cache when identity validation requests it, so a
custom source cannot reuse tokens produced without that implicit source field.
The fitted object-tokenizer state and token-model checkpoints are unchanged.

## Shared graph recipe slots

`data.amount_field` names the transaction event's numeric amount in graph inputs,
future-aggregate targets and raw probe features. Graph columns retain canonical
amount names; transfer amounts retain `TransferEdge.amount` semantics. Encoder
manifests bind the selected event field, so same-shaped schemas cannot silently
reuse weights under a different amount definition.

Graph history and both sequence controls use `model.composition.position`.
Graph configs default explicitly to `time_rope`; `nope` disables history TimeRoPE
while retaining the same causal masks and within-event/calendar encodings.
Custom context-history factories receive a keyword `position`, and custom
`ContextHistorySpec.build` methods receive the same keyword; implementations
must honor it or reject unsupported positions. NoPE and TimeRoPE are the
supported graph-history position specs.

Pretrain-only graph runs resolve, fit and persist no sequence tokenizer, for
both supervised and FutureSubgraph objectives. Supervised graph labels still use
the same cutoff-truncated sequence-label rule. Full/downstream runs fit and
persist tokenizers because their controls or hybrid consume history batches.
`PreparedGraphData.tokenizer` and `GraphBuildContext.sequence` are consequently
optional, and `graph_specs` returns no sequence spec when histories are unused.

Graph recipes currently reject `data.token_cache` during configuration
validation; they do not consume the token-cache path.


Graph source validation also applies when no tokenizer is built. Label-like
numeric/categorical/text keys are rejected, and an amount field with no finite
value in eligible training-owner history is a schema error. Correct a misspelled
source field or supply an observed finite amount. Individual missing event
amounts retain their masks. Typed Python sections
preserve whether position was explicitly supplied, giving the same graph
default as YAML while retaining explicit `nope` selections.


Raw probe aggregation maps NaN and either infinity to the same zero contribution
as an omitted event amount. This applies to object and cached raw features,
including existing caches at read time. Finite-valued inputs, event counts and
calendar features are unchanged. Graph recipes still require a finite amount
in eligible training history and retain their per-event missing-value masks.
