# Migration from 2.0.0a1 to 2.0.0a2

2.0.0a1 (tag `v2.0.0a1`) is the SDK the GTC Berlin 2026 training lab ships.
2.0.0a2 has one recipe per reference architecture, runs every stage through
`tfm <stage> --recipe <slug> [--config <variant>]`, and groups optional
config knobs into sub-sections. The per-recipe `train.py` / `infer.py` /
`evaluate.py` / `report.py` / `smoke_test.py` scripts and the
`tfm.runtime.decoder` and `tfm.runtime.kvt` modules are gone.

## Configs

Every 2.0.0a1 key either moved, with the same meaning and default, or was
removed. A 2.0.0a1 config fails to load with an error naming each key's
replacement. `tfm migrate-config` rewrites it and checks that the result
loads:

```bash
uv run tfm migrate-config path/to/2.0.0a1/config.yaml --out config.yaml
```

The original's comments are not carried over. A removed key is dropped only
when its value could not have changed the run, and the command reports each
change it made. It refuses a setting 2.0.0a2 cannot run: overlapping
pretraining windows, a packed row length other than the decoder's context,
or joint-fusion `cross_layers` / `plr_frequencies` other than their defaults.

| 2.0.0a1 | 2.0.0a2 |
|---|---|
| `data.pretrain_window_events`, `data.pretrain_max_tokens` | `data.pretrain_windows: {events, max_tokens}` |
| `training.optimizer.muon_learning_rate`, `muon_momentum`, `muon_adjust_lr` | `training.optimizer.muon: {learning_rate, momentum, adjust_lr}` |
| `evaluation.history_window_probe`, `history_window_max_rows`, `history_window_train_negatives_per_positive` | `evaluation.history_window: {enabled, max_rows, train_negatives_per_positive}` |
| `fraud_task.train_head`, `head_loss_weight`, `head_probe_only` | `fraud_task.supervised_head: {enabled, loss_weight, probe_only}` |
| `training.backend: nemo` | `training.backend: fsdp2`; `nemo` now raises with this hint |
| `data.pretrain_window_stride`, `training.packing_seq_length`, `fraud_task.finetune.cross_layers`, `plr_frequencies` | removed: windows never overlap, packed rows are `decoder.max_seq_len` tokens, and joint fusion uses `FineTune`'s defaults |

## Checkpoints

Weights are unchanged. A 2.0.0a1 run directory's `model.pt` loads into the
model its migrated `config.yaml` builds. The lab's Blueprint v2 checkpoint
(`blueprint_v2_lab_tuned`) migrates to
[`benchmarks/ablations/blueprint_v2_final_d.yaml`](../../benchmarks/ablations/blueprint_v2_final_d.yaml)
on every section but `evaluation`, where candidate D also declares the fixed
XGBoost setting and the surprise arm that 2.0.0a1 scored from the lab
notebooks; `tests/unit/test_config_migration.py` checks both.

| 2.0.0a1 | 2.0.0a2 |
|---|---|
| `recipes/tabformer_hf_decoder/config.yaml` | `recipes/blueprint_v1/config.small.yaml` (`--config small`) |
| `recipes/tabformer_hf_decoder/config.gb10.yaml` | `recipes/blueprint_v1/config.yaml` |
| `recipes/tabformer_hf_decoder/config.gb10_cached.yaml` | `recipes/blueprint_v1/config.cached.yaml` (`--config cached`) |
| `recipes/decoder_fraud_baseline/config.yaml` | `recipes/blueprint_v1/config.smoke.yaml` (the same eager decoder on generated data) |
| `recipes/profile_history_kvt/config.yaml` | `recipes/pragma_like/config.smoke.yaml` |
| `recipes/profile_history_kvt/config.pragma_*.yaml`, `config.synth_1m.yaml` | `recipes/pragma_like/` (same names) |
| `recipes/blueprint_v2_hybrid/config.yaml` | `recipes/blueprint_v2/config.smoke.yaml` |
| `recipes/blueprint_v2_hybrid/config.lab_tuned.yaml` | `recipes/blueprint_v2/config.yaml` |
| The lab checkpoint's `config.yaml` (`config.lab_tuned.yaml` at 3,000 steps, LoRA rank 16) | `benchmarks/ablations/blueprint_v2_final_d.yaml` |
| `recipes/blueprint_v2_hybrid/config.pragmatiq.yaml` | `recipes/blueprint_v2/config.scale.yaml` (`--config scale`) |
| `recipes/blueprint_v2_hybrid/config.lab.yaml`, `config.lab_v1_flat.yaml` | `benchmarks/ablations/blueprint_v2_lab.yaml`, `blueprint_v2_lab_v1_flat.yaml` |
| `recipes/blueprint_v2_hybrid/pragmatiq_world.yaml` | `configs/data/pragmatiq/world.yaml` |
| `recipes/building_block_comparison/` | `benchmarks/ablations/building_blocks/` |
| `notebooks/tabformer_hf_decoder/`, `notebooks/decoder_fraud_baseline/` | `notebooks/blueprint_v1/` |
| `notebooks/blueprint_v2_hybrid/`, `profile_history_kvt/`, `building_block_comparison/` | `notebooks/pragmatiq/` |
| `uv run python recipes/<r>/report.py --config <path>` | `uv run tfm report --recipe <r> --config <variant or path>` |
| `torchrun ... recipes/<r>/train.py` | `torchrun ... -m tfm.cli.main train --recipe <r>` |
| `tfm cache-tokens --config <path>` | `tfm cache-tokens --recipe <r> --config <variant>`, or `--config <path>` |

Result records under `benchmarks/results/` keep the recipe names they were
recorded under; [the results index](../../benchmarks/results/README.md) maps
them to the current configs.
