The Kumo SDK implements a pythonic interface for users to programmatically
interact with a configured Kumo service.

## Installation

The Kumo SDK is available for Python 3.10 to Python 3.14. To install, simply run

```
pip install kumoai-studio
```

Use this SDK to connect to a configured Kumo service. The separate
`kumo-engine` package provides the in-process Python interface.

## Looking up projects

Every SDK session has one active project. You can retrieve another visible
project by its display name or immutable Kumo ID without changing that active
project:

```python
import kumoai_studio

kumoai_studio.init()  # Selects the canonical Default project.
fraud = kumoai_studio.get_project("Fraud Detection")

assert kumoai_studio.current_project().name == "Default"

# Pass the stable ID to project-scoped objects when needed.
events = kumoai_studio.BigQueryConnector(
    name="events",
    project_id="company-data-prod",  # Google Cloud project ID
    dataset_id="events",
    kumo_project_id=fraud.id,         # Kumo project ID
)
```

Use `kumoai_studio.set_project(fraud)` when you do want to change the active project.

## Multi-categorical string columns

For a scalar string containing several categories, set the proven delimiter
on the column. Kumo persists it in the table definition, so metadata
validation, snapshots, and training all split the values identically. Comma,
pipe, semicolon, and tab are supported.

```python
interests = kumoai_studio.Column(
    name="interests",
    stype="multicategorical",
    dtype="string",
    multicategorical_delimiter="|",
)
```

Do not set a delimiter for native `stringlist` or `intlist` columns; their
array structure already separates categories. When metadata inference detects
a delimiter, the SDK retains the inferred value automatically.

## Google identities stay credential-free in the SDK

Administrators assign BigQuery and GCS identities to project-owning groups.
Users can inspect the safe authentication mode and pass the identity to any
number of project connectors, but private keys and workload tokens never enter
SDK code. Workload identity is preferred when the deployment enables it.

```python
identity = kumoai_studio.get_identity("Production Google")
print(identity.config.authentication.mode)
# "workload_identity" or "service_account_key"

events = kumoai_studio.BigQueryConnector(
    name="events",
    project_id="company-data-prod",
    dataset_id="events",
    identity=identity,
)
```

Omit `identity` to ask the server to select the only authorized identity that
can access the exact connector target. Connector constructors never accept
Google keys, source credentials, or access tokens.

## Exact prediction output paths

For hosted prediction, use a rootless object-store connector and specify each
artifact's destination separately:

```python
from kumoai_studio import ADLSConnector
from kumoai_studio.artifact_export.config import OutputConfig

output = ADLSConnector(identity=identity)
config = OutputConfig(
    output_connector=output,
    output_paths={
        "predictions": "abfss://exports@account.dfs.core.windows.net/predictions/project/",
        "embeddings": "abfss://exports@account.dfs.core.windows.net/embeddings/project/",
    },
)
result = trainer.predict(graph=graph, output_config=config)
```

S3 and GCS use the same interface with their respective connectors and URI
schemes. Keys select the artifacts, so do not also set `output_types` or
`output_table_name`. No artifact suffix is added. A trailing slash requests a
dataset directory for either one or multiple parts; paths without a file
extension are also treated as directories. Explicit `.parquet`/`.csv` paths
retain existing single-file/multipart export behavior. Rooted connectors accept
relative paths within their root.

For existing results, `result.export()` accepts the same configuration with
one artifact per call. The artifact must have been generated by the prediction
job. Existing directory ownership/retry rules still apply; a different export
requires an empty destination. Existing `output_table_name` configurations retain
their historical suffix behavior.

Prediction and embedding destinations are exported independently. If a later
output fails, earlier outputs may already be complete and the failed directory
may contain partial parts without `_SUCCESS`. Retry the retained result's
`export()` with the same destination, one artifact per call. Directory retries
remove an existing `_SUCCESS` before copying and publish it again only after
that destination completes; this requires permission to delete that marker.
Readers should wait for `_SUCCESS` before consuming a directory. Exports do
not provide a transaction across destinations, atomic single-file replacement,
or isolation from concurrent writers or readers.

## Development

From a prepared repository environment, install the colocated API and SDK:

```bash
uv pip install -e packages/kumo-api
uv pip install -e packages/kumo-sdk
```

Package automation lives in `.github/workflows/kumo-sdk-*` at the repository
root. See the [publication guide](../../scripts/release/README.md#service-sdk-publication)
for release controls.
